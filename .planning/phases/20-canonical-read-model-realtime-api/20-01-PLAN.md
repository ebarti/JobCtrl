## Task 2: Build summary/audit JSON in both projection builders

type: implementation
files:
  - `apps/api/src/projections.ts`
  - `workers/automation/src/jobhunter/infrastructure/projections/projection_builder.py`
action:
  - Load posted compensation facts from `job_posted_compensation_facts` and market estimates from `job_market_compensation_estimates`.
  - Build a compact summary with separate `posted` and `market` state sections.
  - Build a detail audit object with separate `posted` and `market` sections.
  - Preserve raw `jobs.salary` only as `legacyRawSalary`; do not parse it during projection refresh.
  - Sanitize market source metadata using the same allowlist boundary as Phase 19.
verify:
  - `corepack pnpm --filter @jobhunter/api exec vitest run test/projections.test.ts -t "compensation"`
  - `uv --project workers/automation run --extra dev pytest -q workers/automation/tests/test_projection_builder.py -q`
acceptance_criteria:
  - Posted and market facts are visibly separate in projection JSON.
  - Missing/corrupt rows produce null-safe, explicit state summaries rather than thrown reads.
  - Projection JSON contains no profile preferences, local paths, credentials, raw benchmark pages, or unauthorized source labels.
