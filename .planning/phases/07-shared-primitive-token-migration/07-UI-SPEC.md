> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn initialized in `apps/web/components.json`; use targeted local edits only |

Source: `.planning/ROADMAP.md`, `.planning/REQUIREMENTS.md`, `07-CONTEXT.md`, `06-VERIFICATION.md`, `apps/web/components.json`, `corepack pnpm dlx shadcn@latest info -c apps/web`.

### Phase Boundary

- Phase 7 hardens shared primitives only: buttons, badges, cards, forms, table/data-grid controls, skeletons, separators, scroll areas, toasts, dialogs, sheets/drawers, dropdowns, popovers, commands, selects, tabs, switches, checkboxes, and tooltips.
- Preserve exports, props, Radix wiring, portals, focus management, keyboard behavior, ARIA semantics, animations, route behavior, API/SSE/query behavior, domain status semantics, and stable control dimensions.
- Do not run uncontrolled `shadcn apply`, do not regenerate the primitive surface wholesale, and do not redefine tokens in Phase 7.
- `apps/web/src/shared/ui` must remain domain-agnostic: no imports from `contexts/`, `views/`, API clients, query hooks, local storage, EventSource, or route modules. Existing `MarkdownDocument.tsx` context selector import is a boundary exception to audit, not a pattern to expand.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, menu item internals, compact separator offsets |
| sm | 8px | Compact element spacing, menu/select item padding, stacked metadata gaps |
| md | 16px | Default element spacing, card and popover inner spacing where dense operation allows |
| lg | 24px | Dialog/sheet/card padding and larger form groups |
| xl | 32px | Dense table row compact height and larger toolbar gaps |
| 2xl | 48px | Comfy density row height and major story layout spacing |
| 3xl | 64px | Storybook canvas/demo section spacing only; avoid in production primitive internals |

Exceptions:

- Button heights stay shadcn-sized: `h-8` small, `h-9` default/icon, `h-10` large.
- App-shell density remains the existing seam: `.app-shell[data-density]` with `--jh-row-height` at 32px compact, 40px regular, and 48px comfy.
- Checkbox remains 16px square; switch remains 36px by 20px unless an implementation task explicitly proves a contrast or hit-target defect.
- Dialog/sheet/drawer close buttons must keep a stable visual target and an accessible name; if enlarged, use a multiple-of-4 dimension and do not shift content.

Source: `07-CONTEXT.md` D-11, `06-VERIFICATION.md`, `apps/web/src/styles/tokens.css`, existing primitive classes.

## Typography

Use exactly these primitive typography roles for new or changed shared UI code:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption / metadata | 12px | 400 | 1.4 |
| Body / controls | 14px | 400 | 1.5 |
| Label / action | 14px | 600 | 1.4 |
| Primitive heading | 18px | 600 | 1.2 |

Rules:

- Use Geist through `font-sans` for primitive body/control text.
- Use JetBrains Mono only for technical values, commands, counters, and existing technical heading surfaces; do not convert ordinary primitive labels to mono.
- Keep the weight set to 400 and 600 only for newly touched primitive text. Existing `font-medium` in copied shadcn internals may remain when behavior-preserving migration would otherwise churn the file; do not introduce additional weights.
- Do not use viewport-scaled type or negative letter spacing.

Source: Phase 6 token contract, `docs/frontend-target.md` §4.8, existing `shared/ui` shadcn conventions.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `background` / `foreground`: light `oklch(1 0 0)` / `oklch(0.145 0 0)`, dark `oklch(0.145 0 0)` / `oklch(0.985 0 0)` | App background, default form controls, dialog/sheet/drawer base surfaces, table body surfaces |
| Secondary (30%) | `card`, `popover`, `secondary`, `muted`: light card/popover `oklch(1 0 0)`, secondary `oklch(0.967 0.001 286.375)`, muted `oklch(0.97 0 0)`; dark card/popover `oklch(0.205 0 0)`, secondary `oklch(0.274 0.006 286.033)`, muted `oklch(0.269 0 0)` | Cards, popovers, dropdown/select/command content, skeletons, helper text backgrounds, tabs list |
| Accent (10%) | `primary` sky: light `oklch(0.5 0.134 242.749)`, dark `oklch(0.443 0.11 240.79)`; `accent` neutral hover: light `oklch(0.97 0 0)`, dark `oklch(0.269 0 0)` | Primary button variant, active checkbox/switch state, selected command/menu/select item, focus rings through `ring-ring`, active tab/sort/filter affordances |
| Destructive | `destructive`: light `oklch(0.577 0.245 27.325)`, dark `oklch(0.704 0.191 22.216)` | Destructive button/badge/toast variants and destructive confirmations only |

Accent reserved for: primary button variant, active toggles, selected menu/select/command rows, active tab/filter/sort affordances, and focus-visible ring color. Do not use accent to decorate every hover state; neutral `accent` hover is allowed for menu/list affordances.

Primitive color rules:

- Use standard shadcn semantic utilities: `bg-background`, `text-foreground`, `bg-card`, `text-card-foreground`, `bg-popover`, `text-popover-foreground`, `bg-primary`, `text-primary-foreground`, `bg-secondary`, `text-secondary-foreground`, `bg-muted`, `text-muted-foreground`, `bg-accent`, `text-accent-foreground`, `border-border`, `border-input`, `ring-ring`, `bg-destructive`, and `text-destructive`.
- Do not introduce legacy utilities or variables: `bg-paper`, `text-ink`, `border-rule`, `ring-info`, `--bg`, `--paper`, `--ink`, `--rule`, `--info`, `--danger`, `--warn`, or `--ok`.
- Do not use `chart-*` tokens for primitive lifecycle or status colors.
- Overlay primitives must use `popover` or background/card token pairs with `border-border`, shadow, and visible focus styles in light and dark modes.

Source: `apps/web/src/styles/tokens.css`, `apps/web/src/styles/globals.css`, `06-VERIFICATION.md`, `07-CONTEXT.md` D-12.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No new product CTA in Phase 7. Preserve caller-provided labels. For primitive story fixtures, use `Save changes`. |
| Empty state heading | For table/grid primitives: `No rows match the current filter.` For generic empty primitive examples: `Nothing to show yet.` |
| Empty state body | `Adjust the filters or clear the search to see more rows.` Use only when the primitive supports body copy; do not add body copy to the current `Empty` primitive unless the implementation plan expands its API. |
| Error state | `Unable to load this content. Try again after checking the local app status.` Use only for story/test fixtures; primitives must not invent product errors. |
| Destructive confirmation | None owned by Phase 7. Destructive variants must preserve the owning feature's confirmation copy and accessible names. Story fixtures may use `Delete draft: This action cannot be undone.` |

Copy rules:

- Shared primitives accept text from callers; they do not hard-code JobHunter domain language except synthetic story/test examples.
- Icon-only controls must have an accessible name via visible text, `aria-label`, or `.sr-only` text. Close controls use `Close`.
- Pagination labels stay stable and explicit: `previous`, `next`, and `Page size`.
- Loading/empty state text in stories and tests must use synthetic data only.

Source: `07-CONTEXT.md` D-02, D-07, D-09; existing `shared/ui` stories/tests.

## Interaction Contract

### Required Primitive States

Every changed primitive must preserve or add evidence for the relevant states below:

| Surface | Required states |
|---------|-----------------|
| Button / badge | default, secondary/outline/ghost/link where supported, destructive, disabled, focus-visible, icon-only accessible name when applicable |
| Input / textarea / select | default, value, placeholder/helper text, disabled, focus-visible, invalid/error story fixture when supported by caller props |
| Checkbox / switch / tabs | checked/on/active, unchecked/off/inactive, disabled, focus-visible, keyboard reachable |
| Card / skeleton / separator / scroll-area | default, dense content, muted/helper presentation, dark-mode readable |
| Table / data-table / filterable-data-grid / table-pager | loading, empty, populated, sorting, filtering, pagination, active filter chips, row activation by Enter and Space where supported, density row-height compatibility |
| Dialog / sheet / drawer | closed trigger, open state, title/description association, close control accessible name, focus trap/return, Escape close, light/dark overlay readability |
| Dropdown / popover / command / select / tooltip | closed trigger, open state, selected/active item, disabled item, keyboard navigation, readable popover surface over dense content |
| Toast / toaster | info/default, destructive/error, action, close control accessible name, stacked viewport behavior |

### Focus And Keyboard

- Keep visible focus rings using `focus-visible:ring-2 focus-visible:ring-ring` or equivalent standard shadcn ring utilities.
- Do not add positive `tabIndex`.
- Do not place `aria-hidden` on focusable elements.
- Prefer native `button`, `input`, `select`, `textarea`, and Radix primitives over custom ARIA. Custom row activation must have role, keyboard, and accessible-state proof.
- Test behavior by role/name where possible; do not snapshot Radix internals.

### Accessibility Deferrals

Known Phase 7 baseline deferrals are already tracked in `docs/backlog.md`:

- `data-table.tsx`: role/aria-sort table semantics.
- `toast.tsx`: `ToastClose` icon-only accessible name.
- Radix/cmdk wrapper story deferrals for dropdown, select, popover, scroll-area, and command.

Phase 7 may fix these, but if any new serious/critical axe deferral is introduced it must be added to `docs/backlog.md` with production file, defect, and story owner. Never silence the Storybook a11y bar without a backlog entry.

Source: `docs/local-reliability-qa.md`, `docs/backlog.md`, `07-CONTEXT.md` D-10 and D-13.

## Verification Contract

Minimum planner/executor verification for Phase 7:

```bash
corepack pnpm web:check
corepack pnpm --filter @jobhunter/web test src/shared/ui/filterable-data-grid.test.tsx
corepack pnpm web:storybook:build
corepack pnpm web:storybook:test
corepack pnpm dlx shadcn@latest info -c apps/web
git diff --check
```

Additional gates:

- Run `corepack pnpm --filter @jobhunter/web test-d` if primitive prop/export types change.
- Run targeted Playwright/browser proof for open overlays, keyboard focus, or density behavior when changed code cannot be proven by unit tests or Storybook interaction tests.
- Run a legacy token scan over `apps/web/src/shared/ui`, `apps/web/.storybook`, and relevant stories.
- Run a dependency-boundary scan for `contexts/`, `views/`, API/query/SSE/local-storage imports in `apps/web/src/shared/ui`.
- If broad `corepack pnpm --filter @jobhunter/web test` still has unrelated inline snapshot failures, preserve scoped verification evidence and carry forward the unrelated failure instead of masking it.

QA safety:

- Use synthetic stories, seeded Playwright harnesses, or disposable workspaces only.
- Do not run auto-apply, browser submission, mailbox scanning, real material generation, destructive profile/database actions, or worker-backed jobs.
- Do not expose real profile data, resumes, generated PDFs, browser profiles, local databases, logs, API keys, OAuth tokens, or application data in evidence.
