## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, dense inline gaps, table cell micro-spacing |
| sm | 8px | Compact controls, nav item padding, form field gaps |
| md | 16px | Default element spacing, card/content gutters |
| lg | 24px | Route section padding and topbar horizontal padding |
| xl | 32px | Major route layout gaps |
| 2xl | 48px | Page-level breaks only |
| 3xl | 64px | Rare full-page separation; not for dense operational panels |

Exceptions:

- Icon-only controls must keep at least a 32px visible box and a 44px effective touch target where space allows.
- Density row heights remain explicit app dimensions aligned to the 4px grid: compact 32px, regular 40px, comfy 48px unless implementation proves a renamed final token is safer.
- Radius uses the preset medium value `--radius: 0.625rem` with derived shadcn radius tokens from the theme probe: `sm = radius * 0.6`, `md = radius * 0.8`, `lg = radius`, `xl = radius * 1.4`.

## Typography

Use exactly these four text sizes and two weights in Phase 6 token/base work. Do not redesign view typography.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 | 1.4 |
| Body | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |

Rules:

- Body font token maps to Geist: `--font-sans`.
- Heading and technical font token maps to JetBrains Mono: `--font-heading` and `--font-mono` where needed.
- Keep dense operational labels small; do not introduce hero-scale type in dashboard cards, tables, drawers, debug views, or apply-review surfaces.
- Preserve existing body copy and route labels unless a class rename requires touching the surrounding element.

## Color

Use the shadcn semantic token API as the public styling contract. Values below are the theme-only output observed from the decoded preset and must be scoped to both light and dark modes using JobHunter's existing `[data-theme="dark"]` model, not an accidental `.dark` split.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background: oklch(1 0 0)` light, `oklch(0.145 0 0)` dark | App body, base route background |
| Secondary (30%) | `--card: oklch(1 0 0)` light, `oklch(0.205 0 0)` dark; `--sidebar: oklch(0.985 0 0)` light, `oklch(0.205 0 0)` dark | Cards, topbar/menu/sidebar surfaces, drawers, tables |
| Accent (10%) | `--primary: oklch(0.5 0.134 242.749)` light, `oklch(0.443 0.11 240.79)` dark | Primary actions, selected nav/menu state, focus emphasis where `--ring` is insufficient |
| Destructive | `--destructive: oklch(0.577 0.245 27.325)` light, `oklch(0.704 0.191 22.216)` dark | Destructive actions and failed/destructive status only |

Accent reserved for: primary action buttons, selected navigation/menu state, active route tabs, focused command/search affordances, and selected controls. Do not use accent for generic borders, every hover state, chart series, or lifecycle statuses.

Required semantic tokens:

- Surface pairs: `--background` / `--foreground`, `--card` / `--card-foreground`, `--popover` / `--popover-foreground`.
- Action pairs: `--primary` / `--primary-foreground`, `--secondary` / `--secondary-foreground`, `--accent` / `--accent-foreground`, `--destructive`.
- Utility tokens: `--muted` / `--muted-foreground`, `--border`, `--input`, `--ring`.
- Data tokens: `--chart-1` through `--chart-5` using amber preset values; chart tokens are for data series only, not lifecycle/status meanings.
- Navigation tokens: `--sidebar`, `--sidebar-foreground`, `--sidebar-primary`, `--sidebar-primary-foreground`, `--sidebar-accent`, `--sidebar-accent-foreground`, `--sidebar-border`, `--sidebar-ring`.
- App-specific status extensions may exist only under clean semantic names such as `--success`, `--success-foreground`, `--success-muted`, `--warning`, `--warning-foreground`, `--warning-muted`, `--info`, `--info-foreground`, and `--info-muted`.

No Phase 6 exit-state legacy names:

- Removed from public token/API surface before Phase 6 is complete: `--bg`, `--paper`, `--paper-2`, `--ink`, `--rule`, `--rule-2`, `--danger`, `--warn`, `--ok`, `--font`, `--mono`, `bg-paper`, `text-ink`, `border-rule`, `ring-info`.
- If a short-lived compile bridge is needed inside one implementation patch, it must be removed before Phase 6 completion.

## Copywriting Contract

This phase should not introduce new product UI copy. The product should still read as the same local-first operational tool.

| Element | Copy |
|---------|------|
| Primary CTA | Preserve existing product CTAs. Dev/setup affordances may use `Apply theme preset` only outside product UI. |
| Empty state heading | Preserve existing empty-state headings. Do not introduce token-migration placeholder empty states. |
| Empty state body | Preserve existing empty-state body copy and next-step instructions. |
| Error state | `Theme setup failed. Check shadcn aliases, Tailwind token mappings, and build output.` |
| Destructive confirmation | None in Phase 6. No destructive product actions are added or changed. |

Interaction copy rules:

- Do not rename route tabs, dashboard labels, status labels, apply-review actions, or audit labels as part of token work.
- If a browser smoke fixture exposes an error banner caused by missing worker/API state, use existing seeded-data QA wording; do not invent product migration copy.
- Any visible warning about legacy tokens must be developer-facing documentation or test output, not product UI.

## Phase-Specific Interaction Contract

| Surface | Contract |
|---------|----------|
| Theme toggle | Existing persisted theme behavior remains. `ThemeProvider` continues to write `data-theme` to `<html>` unless the implementation deliberately migrates all CSS, Storybook, and QA to a new selector. |
| Density selector | Existing `data-density` behavior remains app-shell scoped. Compact, regular, and comfy row heights remain visible on table/list surfaces. |
| App shell | Body, topbar, nav, global search, connection status, route tabs, and app content use standard semantic tokens without route, search-param, or workflow changes. |
| Focus | Keyboard focus rings must be visible on buttons, nav tabs, inputs, selects, dropdown items, dialog/sheet controls, data-grid headers, and destructive controls in light and dark. |
| Menus/overlays | Popover/dropdown/select/dialog/sheet/toast surfaces use `popover` or card/surface token pairs and remain readable over dense Jobs, Apply Review, artifact/PDF, and dark-mode surfaces. |
| Status semantics | Domain status color meanings are preserved through explicit semantic extension tokens or typed tone helpers. Do not flatten success/warning/info/running/failed/blocked/stale/missing into chart tokens or generic primary/secondary colors. |
| Safety | Browser proof uses synthetic or seeded data only. Do not run auto-apply, browser submission, mailbox scanning, real material generation, destructive profile/database actions, or worker-backed jobs. |

Visual hierarchy: the primary visual anchor for Phase 6 is the app shell/topbar/nav token application. Secondary anchors are the theme and density controls plus one popover/dropdown surface used to prove overlays inherit the new token contract.
