# 18-01 Posted Compensation Parser And Persistence

<objective>
Add a deterministic posted-compensation fact model, parser, and SQLite persistence path that keeps the legacy `jobs.salary` string as raw fallback while storing structured parse facts in a separate canonical table.
</objective>

<tasks>

## Task 1: Domain Fact Model And Parser

**type:** implementation
**files:**
- `workers/automation/src/jobhunter/domain/compensation/__init__.py`
- `workers/automation/src/jobhunter/domain/compensation/posted.py`
**action:**
- Add immutable Python value objects for posted compensation facts, parse states (`missing`, `unparseable`, `ambiguous`, `parsed_range`), components, periods, warning codes, confidence, parser version, bounded source text, and legacy raw fallback.
- Implement a deterministic parser that accepts a bounded salary/source string and returns:
  - `missing` when no salary text exists.
  - `unparseable` when text exists but no compensation amount can be safely extracted.
  - `ambiguous` when multiple compensation components or numeric meanings are present and a primary salary range cannot be safely selected.
  - `parsed_range` only when minimum/maximum amount, currency or missing-currency warning, period or missing-period warning, component, confidence, and warnings are explicit.
- Support annual, monthly, hourly, one-sided, broad-range, OTE, bonus, commission, equity, missing-currency, and missing-period cases without LLMs, network calls, source registry reads, profile-floor comparisons, ranking, filtering, or scoring.
- Populate annualized values only when an `annualization_assumption` string is present; hourly and monthly conversions must carry explicit warning/assumption text.
- Bound stored source text to a small excerpt; never copy full descriptions or provider raw payloads.
**verify:**
- Parser output has an explicit parse state for every supported input class.
- Annualized values are absent unless an assumption is present.
- Parser has no imports from scoring, apply, external providers, LLMs, HTTP clients, or browser automation.
**done:**
- A pure parser returns durable posted-compensation facts with inspectable state and warnings.

## Task 2: Canonical SQLite Table And Repository

**type:** implementation
**files:**
- `workers/automation/src/jobhunter/database.py`
- `workers/automation/src/jobhunter/infrastructure/compensation/__init__.py`
- `workers/automation/src/jobhunter/infrastructure/compensation/sqlite_repository.py`
**action:**
- Add `ensure_posted_compensation_tables(conn)` and call it from `init_db`.
- Create `job_posted_compensation_facts` keyed by `tenant_id` and `job_url`, with columns for source text, legacy raw salary, parse state, currency, period, component, minimum, maximum, annualized minimum/maximum, annualization assumption, confidence, warnings JSON, parser version, source hash, and parsed timestamp.
- Add a SQLite repository that can upsert a fact, read a fact by tenant/job URL, and idempotently backfill all current jobs from `jobs.salary`.
- Keep `jobs.salary` unchanged; structured facts are additive and stored separately.
- Use deterministic JSON serialization for warning arrays and safe row mapping for optional normalized fields.
**verify:**
- `init_db` creates the canonical fact table idempotently.
- Backfill creates or updates fact rows without mutating `jobs.salary`.
- Repository reads return the same parse state, source text, raw fallback, values, confidence, and warnings that were persisted.
**done:**
- Posted compensation facts are durable in a canonical local table separate from legacy job rows.

## Task 3: Discovery Integration

**type:** implementation
**files:**
- `workers/automation/src/jobhunter/discovery/jobspy.py`
**action:**
- After JobSpy insert/refresh preserves the legacy `salary` string, parse the bounded salary text and upsert the posted compensation fact through the repository.
- Keep the existing `salary = COALESCE(NULLIF(?, ''), salary)` compatibility behavior intact.
- Do not emit full descriptions, provider payloads, credentials, local paths, or private account state into events or fact rows.
- Do not add read-model projection, SSE invalidation, score, rank, filter, apply readiness, or material-generation behavior.
**verify:**
- Existing discovery tests that preserve salary on rediscovery continue to pass.
- New repository tests prove parsing/backfill works even when a rediscovery row has no new salary text.
**done:**
- New and refreshed discovered jobs get posted compensation facts without losing legacy salary fallback.
