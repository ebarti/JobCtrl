# 18-02 Posted Compensation Inspection API

<objective>
Expose persisted posted-compensation facts through a narrow read-only local API and shared contract so the facts are inspectable before Phase 20 adds canonical job list/detail propagation and realtime invalidation.
</objective>

<tasks>

## Task 1: Shared TypeScript Contract

**type:** implementation
**files:**
- `packages/contracts/src/schemas.ts`
**action:**
- Add posted-compensation literal alphabets for parse state, component, period, and warning codes.
- Add `PostedCompensationFact`, `PostedCompensationFactNotRecorded`, and `PostedCompensationFactResponse` DTOs with discriminated read status and parse state:
  - `recordStatus: "recorded"` carries a `fact` with one of the parser states.
  - `recordStatus: "not_recorded"` carries the existing job key and legacy raw salary fallback only, so missing canonical backfill is explicit and not misreported as parsed data.
  - `parsed_range` may include normalized currency, period, component, minimum, maximum, annualized values, annualization assumption, confidence, and warnings.
  - `missing`, `unparseable`, and `ambiguous` include source text/raw fallback/confidence/warnings only where applicable and must not pretend to have normalized range fields.
- Include safe fields only: tenant/job id, exact bounded source text, legacy raw salary fallback, parse state, parser version, parsed timestamp, source hash, confidence, warning codes/messages, and normalized values when legal.
- Do not add profile compensation preferences, credentials, local paths, provider payloads, benchmark rows, raw descriptions, or private account data.
**verify:**
- API and client can import the DTOs from `@jobhunter/contracts`.
- Illegal normalized-field combinations are not represented by the DTO.
**done:**
- Shared TypeScript consumers have a narrow posted-compensation inspection contract.

## Task 2: Read-Only API Helper And Route

**type:** implementation
**files:**
- `apps/api/src/posted-compensation-facts.ts`
- `apps/api/src/server.ts`
- `packages/api-client/src/client.ts`
**action:**
- Add a helper that reads `job_posted_compensation_facts` directly and maps rows to the shared DTO.
- If no fact row exists for an existing job, return an explicit `recordStatus: "not_recorded"` response with the current legacy raw salary fallback; do not parse, backfill, update, or persist from a GET route.
- Add `GET /v1/jobs/:jobKey/compensation/posted` as a read-only endpoint using `withDb` and `decodeRouteParam`.
- Return `404` for unknown jobs; return `{ ok: true, recordStatus: "recorded", fact }` for known jobs with a canonical row, including when the parse state is `missing`, `unparseable`, or `ambiguous`.
- Add `postedCompensationFact(jobKey)` to the shared API client.
- Do not add POST/PATCH mutation routes, list/detail read-model fields, SSE events, query filters, sorting, ranking, score changes, apply-readiness changes, or market-estimate behavior.
**verify:**
- Route reads from canonical rows and performs no writes, parser calls, projection refresh extension, or React parsing.
- Unknown jobs return a safe not-found response.
- Existing `/v1/jobs` and `/v1/jobs/:key` response shapes remain compatible in this phase.
**done:**
- Posted-compensation facts are inspectable through a narrow local API endpoint.
