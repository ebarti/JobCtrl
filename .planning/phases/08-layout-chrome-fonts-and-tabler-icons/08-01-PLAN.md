# Phase 8 Plan 01 - Shell Chrome And Font Contract

## Goal

Move the app shell chrome onto the Phase 6/7 shadcn semantic-token baseline while preserving the current dense operational shell behavior.

## Requirements Covered

- LAYOUT-01: app shell, topbar, navigation, global search, theme toggle, density control, connection status, tabs, and menu surfaces adopt preset visual language without behavior changes.
- LAYOUT-02: Geist and JetBrains Mono remain the Vite/Storybook font stacks with stable dense layouts.
- LAYOUT-04: compact, regular, and comfy density continue to drive row height and scanning fit.
- LAYOUT-05: topbar/menu translucency remains readable in light/dark and over dense route surfaces.

## Tasks

1. Preserve shell structure and behavior seams.
   - Keep `.app-shell` and `data-density={density}` on the shell root.
   - Keep `Topbar` composition: brand, `NavBar`, global search, density select, `ThemeToggle`, `ConnectionStatusPill`.
   - Keep `NavBar` labels/routes and `activeProps={{ className: "on" }}` unchanged.
   - Keep global search Enter behavior: `to: "/jobs"`, search `{ q: query.trim(), page: 1 }`.
   - Keep `ConnectionStatusPill` health/SSE reads, labels, `aria-live`, and alert/status roles unchanged.

2. Retokenize shell chrome in `globals.css`.
   - Use standard semantic tokens: `--card`, `--popover`, `--muted`, `--accent`, `--border`, `--input`, `--ring`, `--foreground`, `--muted-foreground`.
   - Apply the default-translucent/subtle menu treatment to topbar, nav, tabs, select/input, connection pill, and banners.
   - Keep the shell dense and utilitarian; no hero, decorative gradients, or route redesign.
   - Prefer opacity/readability over decorative blur if translucent surfaces lose contrast.

3. Preserve and prove font contracts.
   - Keep `@fontsource-variable/geist` and `@fontsource-variable/jetbrains-mono` imports in `globals.css`.
   - Keep `--jh-font-sans`, `--jh-font-heading`, `--jh-font-mono` in `tokens.css`.
   - Keep `@theme inline` mappings for `--font-sans`, `--font-heading`, and `--font-mono`.
   - If adding fallback stability, use progressive enhancement only; do not add viewport-width font scaling.

4. Preserve density semantics.
   - Keep `.app-shell[data-density]` as the density root.
   - Keep `--jh-row-height`: compact `32px`, regular `40px`, comfy `48px`.
   - Do not move density to `<html>` or rely on style queries for required behavior.

5. Extend static token contract tests only where necessary.
   - Add assertions for shell selectors, font mappings, or menu/chrome token usage if implementation changes those contracts.
   - Do not create a second token contract test file.

## Acceptance Criteria

- Shell components preserve route/search/preference/status behavior.
- Topbar, nav, tabs, global search, density select, theme toggle, connection pill, and banners use semantic shadcn tokens.
- Font imports and CSS variables remain wired for app and Storybook global CSS.
- Density row-height values remain unchanged and scoped to `.app-shell[data-density]`.

## Risks And Guards

- Risk: visual polish hides worker/offline state. Guard: preserve `ConnectionStatusPill` labels, live regions, and destructive status styling.
- Risk: topbar token changes reduce dark-mode readability. Guard: browser proof in Plan 04 must inspect computed topbar, nav, input, select, pill, and banner surfaces.
- Risk: density/font changes affect table scanning. Guard: Playwright proof must verify `/jobs` at compact, regular, and comfy densities.
