# Phase 8 Plan 04 - Browser QA, Audit, And Closeout

## Goal

Verify the implemented shell/icon/font migration in the browser, record explicit icon deferrals, and close Phase 8 only after required web checks and product-path QA pass.

## Requirements Covered

- LAYOUT-01 through LAYOUT-05.
- QA safety constraints QA-05 and QA-06, as applicable to Phase 8 evidence.

## Files

- `apps/web/e2e/tests/token-foundation.spec.ts`
- Optional new Playwright spec under `apps/web/e2e/tests/`
- `.planning/phases/08-layout-chrome-fonts-and-tabler-icons/08-ICON-AUDIT.md`
- `.planning/phases/08-layout-chrome-fonts-and-tabler-icons/08-VERIFICATION.md`
- `.planning/phases/08-layout-chrome-fonts-and-tabler-icons/08-REVIEW.md`
- `.planning/ROADMAP.md`
- `.planning/REQUIREMENTS.md`
- `.planning/STATE.md`

## Tasks

1. Extend browser proof.
   - Reuse or extend `token-foundation.spec.ts` for app-shell proof.
   - Verify topbar, active nav, global search, density select, theme toggle, and connection pill are visible and readable.
   - Verify light and dark computed shell surfaces are painted and non-transparent.
   - Verify compact, regular, and comfy density set `.app-shell[data-density]` and `--jh-row-height`.
   - Verify density and theme persist across route navigation and reload where stable.
   - Verify global search Enter reaches `/jobs` with trimmed `q` and `page=1`.
   - Verify changed icons render without breaking accessible control names.

2. Add route fit proof within Phase 8 boundaries.
   - Cover at least `/dashboard` and `/jobs` in browser proof.
   - Prefer synthetic API/MSW-backed data already used by web E2E.
   - Do not attempt the full Phase 10 route matrix in this phase.

3. Run required validation commands.
   - `corepack pnpm --filter @jobhunter/web test` targeted to changed files.
   - `corepack pnpm web:check`.
   - `corepack pnpm web:build`.
   - `corepack pnpm --filter @jobhunter/web e2e -- tests/token-foundation.spec.ts` or equivalent focused shell spec.
   - `rg "lucide-react|@tabler/icons-react" apps/web/src apps/web/package.json`.
   - `git diff --check`.
   - Run Storybook build/test if shared stories, provider behavior, or story-visible primitives changed.

4. Perform code review and QA loops.
   - Run a reviewer against the changed Phase 8 files.
   - Fix all Blocker/High findings before closeout.
   - Run a QA check against the product-path evidence.
   - Fix all Blocker/High QA findings before closeout.

5. Record closeout artifacts.
   - Create `08-ICON-AUDIT.md` with migrated icons and remaining deferrals.
   - Create `08-VERIFICATION.md` with exact commands, pass/fail results, browser evidence, and skipped verification with reasons.
   - Create `08-REVIEW.md` with review/QA findings and resolution status.
   - Update `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md`, and `.planning/STATE.md` only after Phase 8 passes required gates.

6. Publish PR.
   - Commit implementation and planning updates in atomic conventional commits.
   - Push a branch stacked on Phase 7: `phase-08-layout-chrome-fonts-and-tabler-icons`.
   - Open a draft PR with conventional title and validation summary.
   - Do not mention automation tooling in commit messages, PR title, or PR body.

## Acceptance Criteria

- Browser proof exercises the shell path in light/dark and compact/regular/comfy density.
- Remaining lucide imports are intentionally documented or absent.
- All required checks pass, or any skipped command has a concrete blocker and Phase 8 is not marked complete.
- Phase 8 state docs are reconciled only after review and QA gates pass.
- A stacked draft PR is created before moving to Phase 9.

## Risks And Guards

- Risk: E2E accidentally depends on real profile/application data. Guard: use existing seeded/synthetic E2E data and avoid screenshots/log dumps containing sensitive artifacts.
- Risk: Storybook Chromium fails under sandbox MachPort constraints. Guard: rerun with approved escalation only when Storybook test is required and document the first failure plus escalated pass.
- Risk: Phase 10 scope creeps into Phase 8. Guard: only prove shell behavior and representative route fit; leave route-wide matrix for Phase 10.
