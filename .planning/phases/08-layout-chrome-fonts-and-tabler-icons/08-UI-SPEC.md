## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Nav/menu item gaps, icon-to-label spacing, compact inline gaps |
| sm | 8px | Topbar control gaps, brand mark gap, banner padding, focus offsets |
| md | 16px | Default shell/control spacing, topbar horizontal gaps, card/header gaps |
| lg | 24px | App-shell horizontal padding and main content gutters |
| xl | 32px | Wide layout separation when chrome wraps |
| 2xl | 48px | Comfy density row height and major route spacing |
| 3xl | 64px | Reserved for page-level spacing outside Phase 8 shell edits |

Exceptions:

- Icon-only or compact icon+label controls must keep a minimum 32px visual height in compact density and a 40px preferred pointer target in regular density.
- `--jh-row-height` remains the density contract: compact `32px`, regular `40px`, comfy `48px`.
- Brand mark may remain `18px` square only if the enclosing link has stable clickable padding and the mark does not drive layout height.
- Connection status dot may remain `6px`; it is decorative state support, not the full target.

## Typography

Use exactly these four size roles for Phase 8 shell/chrome work. Do not scale font size with viewport width.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px regular density baseline | 400 | 1.5 |
| Label | 12px compact chrome labels/status text | 400 | 1.4 |
| Heading | 16px route/chrome headings where touched | 600 | 1.2 |
| Display | 20px maximum for shell-adjacent brand or route chrome only | 600 | 1.2 |

Font contract:

- Body text uses `var(--font-sans)` / `var(--jh-font-sans)` with `"Geist Variable"` first and system sans fallbacks.
- Heading, brand mark, status numerals, and technical metadata may use `var(--font-heading)` or `var(--font-mono)` with `"JetBrains Mono Variable"` first.
- Keep weights to regular `400` and semibold `600`; do not introduce bold `700` in new shell styling unless preserving an existing brand affordance.
- Font fallback stability may use `font-size-adjust` as progressive enhancement only; the base fit must work without it.
- Density may adjust shell-local font size only through explicit `.app-shell[data-density]` rules already present in `tokens.css`; do not use viewport-width font scaling.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--foreground` | Page background, main content area, default readable text |
| Secondary (30%) | `--card`, `--popover`, `--muted`, `--border`, `--input` | Topbar surface, translucent menu/chrome surface, nav hover/current route, global search, density select, banners, separators |
| Accent (10%) | `--primary`, `--primary-foreground`, `--ring`, plus subtle `--accent` for menu hover/current state | Brand mark emphasis, current navigation affordance, focus-visible rings, selected menu/tab state, high-emphasis shell controls only |
| Destructive | `--destructive` | Worker unavailable, connection lost, destructive warning surfaces only |

Accent reserved for:

- Small brand mark or equivalent shell identity accent.
- Current route/nav state and open/current menu item state.
- Keyboard focus rings on shell controls.
- Theme and density controls when focused or active.
- Connection status dot only when the status is live/open and the implementation explicitly maps live to a semantic success token.

Do not use accent for:

- Every interactive control by default.
- Domain/status remapping for pipeline, score, artifact, apply, discovery, or audit states; that is Phase 9.
- Chart/data-series semantics.

Chrome surface contract:

- Primary visual anchor is the topbar current-route/nav cluster, with global search as the primary interactive control.
- Topbar uses the preset default-translucent/subtle menu treatment: a readable `--card` or `--popover` surface with controlled translucency, border from `--border`, and active/hover menu states from `--muted` or `--accent`.
- Topbar/menu translucency must remain readable over Jobs, Apply Review, artifact/PDF preview, and dark-mode surfaces. If translucency lowers contrast, prefer a more opaque semantic surface over a blurred decorative effect.
- Keep the UI quiet and operational. No hero, marketing shell, decorative gradients, orb backgrounds, or route redesign.

## Shell And Interaction Contract

Phase 8 owns visual treatment, fonts, and user-visible iconography for app shell/chrome only.

In scope:

- `AppShell`, `Topbar`, `NavBar`, `ThemeToggle`, `ConnectionStatusPill`.
- Topbar, brand mark, nav links, global search, density select, theme toggle, connection pill/banner, route tabs and menu states where they are chrome.
- Font loading/usage proof for Vite and Storybook.
- Visible lucide-to-Tabler migration or explicit mapping/deferral.

Out of scope:

- Route structure, route labels, route groupings, loaders, search-param contracts, mutations, query keys, SSE invalidation behavior, API calls, worker behavior, and domain workflows.
- Domain/status tone remapping for scoring, pipeline, apply, materials, discovery, audit, stale/missing/blocked states.
- Final dependency cleanup; removing `lucide-react` is Phase 11 unless imports are already zero and the phase plan explicitly includes cleanup.

Required behavior preservation:

- `AppShell` keeps `.app-shell` and `data-density={density}`.
- Density remains scoped through `.app-shell[data-density]` and `--jh-row-height`.
- Theme and density persistence keep storage key `jh:ui-preferences`, version `1`, and the existing serialized shape unless a failing test proves migration is required.
- The pre-paint theme script in `apps/web/index.html` keeps preventing theme flash.
- Global search still navigates on Enter only when the trimmed query is non-empty: `to: "/jobs"`, search `{ q: query.trim(), page: 1 }`.
- `NavBar` still uses TanStack Router `Link` and `activeProps={{ className: "on" }}`.
- `ConnectionStatusPill` still reads EventStream status and health query, keeps `aria-live`, and keeps alert/status roles for banners.
- No direct `localStorage`, `EventSource`, `apiClient`, `queryClient`, or platform calls may be added to shell components outside existing providers/ports.

## Icon Contract

Target library: `@tabler/icons-react`.

Rules:

- Migrate user-visible lucide icons in shell/chrome to Tabler equivalents.
- Preserve action meaning and accessible names. Decorative icons must stay `aria-hidden="true"`.
- Icon sizing in shell controls: 16px preferred, 14px allowed for existing compact label+icon controls if the enclosing control target remains stable.
- Icon stroke should use current text color by default and must not introduce one-off colors outside semantic tokens.
- Icon-only controls require an accessible name and stable dimensions; label+icon controls may keep visible text.
- If a lucide icon cannot be safely migrated in Phase 8, the plan or closeout must record: source file, lucide icon, intended Tabler equivalent or reason for deferral, and whether it is user-visible chrome, shared primitive affordance, or domain/status UI.

Initial import audit found user-visible lucide imports in:

- Shell: `apps/web/src/shared/layout/ThemeToggle.tsx`.
- Shared UI affordances: command, select, filterable data grid, dropdown menu, copyable command, checkbox, dialog, toast, sheet.
- Domain/view controls: Apply Review external link, scoring buttons, pipeline stage trigger, discovery controls, profile editor, materials buttons.

Phase 8 priority order:

1. Shell/chrome imports first: `ThemeToggle`, nav/menu/search/density/status affordances if icons are added or changed.
2. Shared primitive user-visible affordances where behavior is unchanged and tests/stories already cover the primitive.
3. Domain/view controls only when they are visible chrome/control icons and the meaning-preserving Tabler mapping is obvious.

## QA Contract

Required commands:

- `corepack pnpm web:check`
- `corepack pnpm web:build`
- Targeted Vitest coverage for changed shell/provider/icon behavior.
- `corepack pnpm --filter @jobhunter/web test src/styles/token-contract.test.ts` if tokens, font mappings, density selectors, or component config assertions change.
- `corepack pnpm --filter @jobhunter/web e2e -- tests/token-foundation.spec.ts` extended or supplemented to prove Phase 8 shell behavior.
- `rg "lucide-react|@tabler/icons-react" apps/web/src apps/web/package.json`
- `git diff --check`

Conditional commands:

- `corepack pnpm web:storybook:build` and `corepack pnpm web:storybook:test` if shared stories, shell stories, providers, primitives, or Storybook globals change.
- `corepack pnpm --filter @jobhunter/web test-d` if public component prop/export types change.

Browser proof must cover:

- Light and dark theme computed shell surfaces: topbar background/border/text, active nav item, global search, density select, theme toggle, connection pill, and connection banner where possible.
- Compact, regular, and comfy density: `.app-shell[data-density]`, `--jh-row-height`, and dense route fit on at least `/jobs`.
- Theme persistence across reload and pre-paint behavior where practical.
- Density persistence across route navigation and reload where practical.
- Global search Enter behavior from the topbar to `/jobs?q=...&page=1`.
- Nav active state and route behavior remain unchanged.
- Icon migration proof: visible chrome icons render, keep accessible names, and retain stable control dimensions.

Safety constraints:

- QA must use synthetic, seeded, or disposable local state only.
- Do not expose profile data, resumes, cover letters, generated PDFs, browser profiles, SQLite databases, logs, API keys, OAuth tokens, or real application data in screenshots, fixtures, or docs.
- Do not run auto-apply, browser submission, mailbox scanning, real material generation, destructive profile/database actions, or worker-backed jobs unless the user explicitly asks.
- Worker/connection status proof may use mocked, seeded, or health-query-controlled state; do not start user-affecting automation just to force a banner.

## Modern Web Guidance Applied

- Container-aware sizing may be used cautiously for shell layout fit, but core density/theme behavior must remain explicit through data attributes and CSS variables.
- Do not use viewport-width font scaling.
- `font-size-adjust` is allowed only as progressive enhancement for fallback stability.
- Do not rely on Firefox-unsupported container style queries for required density/theme behavior.
