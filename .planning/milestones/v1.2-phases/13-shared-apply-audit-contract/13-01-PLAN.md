# 13-01 Contract And API Derivation

## Goal

Define one shared apply-audit DTO and derive it from API/read-model source facts for both Apply Review queue items and Job Detail.

## Tasks

- Add `ApplyAudit` state, fact, source, and DTO types to `packages/contracts/src/schemas.ts`.
- Add `applyAudit` to `ApplyReviewQueueItem` and `JobDetail`.
- Create an API/read-model helper that derives `ApplyAudit` from:
  - application URL
  - resume, cover, and PDF material availability
  - current stage/state/error
  - latest apply run status/result
  - score eligibility hard blockers and warnings
- Use the helper in `apps/api/src/application-feedback.ts`.
- Query latest apply-run context in `apps/api/src/read-model.ts` and use the same helper in `getJobDetail`.
- Keep legacy `materials` and `blockers` fields for compatibility.
- Extend API tests for ready, preparing, blocked, repair, failed apply-run, and missing-source cases.

## Threat Model

- **Sensitive data exposure:** Do not expose raw resume/profile/log content in the DTO; facts are short operational labels and source statuses.
- **Integrity risk:** Do not let web views recompute readiness from partial fields.
- **Availability risk:** Additive contract fields must not break existing compatibility fields.
