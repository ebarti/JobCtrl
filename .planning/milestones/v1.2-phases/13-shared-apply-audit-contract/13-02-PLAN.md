# 13-02 Apply Review Consumption

## Goal

Make Apply Review consume the shared audit DTO for readiness/status display without changing the broader layout.

## Tasks

- Replace Apply Review source-of-truth readiness logic with formatting around `item.applyAudit`.
- Update queue tags, selected header tag, summary note, and status counts to use the shared DTO.
- Add a compact fact/source explanation for missing prerequisites, hard blockers, and eligibility concerns.
- Update web fixtures to include `applyAudit`.
- Update Apply Review tests for canonical status labels/summaries and failed run explanations.
- Keep decision controls, PDF/text preview, job-detail overlay button, and material inspector behavior unchanged.

## Threat Model

- **Misleading UI risk:** Missing facts must not be hidden; render explicit fact rows when `applyAudit` carries them.
- **Action safety risk:** Approval controls must remain review decisions only and must not dispatch apply automation.
- **Regression risk:** Existing material preview and drawer overlay tests must still pass.
