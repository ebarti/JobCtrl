# 19-01 Plan: Market Estimate Domain And Persistence

<objective>
Add deterministic Python market-estimate facts for Europe public baselines and persist them in canonical SQLite rows separate from posted compensation facts and future projections.
</objective>

<tasks>

## Task 1: Add market-estimate domain model and deterministic estimator

type: implementation
files:
  - `workers/automation/src/jobhunter/domain/compensation/market.py`
  - `workers/automation/src/jobhunter/domain/compensation/__init__.py`
action:
  - Define immutable dataclasses for `MarketCompensationEstimate`, `MarketSourceSnapshot`, `MarketConfidenceFactor`, and a deterministic local `PublicMarketBaseline` fixture/input row.
  - Define explicit unions for estimate state (`not_requested`, `unsupported`, `source_unavailable`, `insufficient_evidence`, `estimated_range`), source IDs (`eurostat_structure_of_earnings`, `esco_occupation_taxonomy`, `spain_ine_salary_structure`), confidence bands, factors, warning codes, and reason codes.
  - Implement a pure estimator that accepts job URL/title/location/seniority/component plus local baseline rows and optional posted annualized range. It must never perform network I/O.
  - Gate `estimated_range` behind supported Europe geography, ESCO occupation mapping, compatible base/gross wage component, non-stale source snapshots, sample support, seniority support, and acceptable source dispersion.
  - Return non-range states with explicit reasons and null range fields: known non-Europe or unsupported component -> `unsupported`; stale required public source -> `source_unavailable`; weak but in-scope support -> `insufficient_evidence`.
  - Emit warnings for aggregate baseline, broad aggregate band, source conflict with posted salary, stale snapshot, low sample count, remote-Europe, Spain-local, EU-wide, non-EU-Europe, and unknown-location assumptions.
verify:
  - `uv --project workers/automation run --extra dev pytest -q workers/automation/tests/test_market_compensation_estimator.py -q`
acceptance_criteria:
  - ESCO source rows can support occupation mapping but cannot produce salary observations by themselves.
  - Only Eurostat, ESCO, and Spain INE source IDs are accepted by the estimator.
  - Non-European or licensed/US source identifiers cannot appear in persisted source snapshots, warnings, or reasons.
  - Range fields are populated only for `estimated_range`.
  - Weak evidence returns `insufficient_evidence` with reasons instead of a precise range.

## Task 2: Add canonical SQLite table and repository

type: implementation
files:
  - `workers/automation/src/jobhunter/infrastructure/compensation/sqlite_market_repository.py`
  - `workers/automation/src/jobhunter/infrastructure/compensation/__init__.py`
  - `workers/automation/src/jobhunter/database.py`
action:
  - Add `ensure_market_compensation_tables(conn)` next to `ensure_posted_compensation_tables(conn)` and call it from `init_db`.
  - Create `job_market_compensation_estimates` keyed by `(tenant_id, job_url)` with safe columns for state, currency, period, component, min/max, confidence band/score, source count, sample count, aggregate bucket, geography scope, occupation code/label, seniority label, safe source snapshots JSON, factor reasons JSON, insufficient/unsupported/source-unavailable reasons JSON, warnings JSON, estimator version, and estimated timestamp.
  - Add an index on `(tenant_id, estimate_state)`.
  - Implement `SqliteMarketCompensationRepository` with `save_estimate`, `get_estimate`, and deterministic `estimate_and_save_job(...)` / `backfill_from_jobs(...)` helpers.
  - JSON serialization must round-trip factors, source snapshots, warnings, and reasons while preserving only allowlisted safe fields.
verify:
  - `uv --project workers/automation run --extra dev pytest -q workers/automation/tests/test_market_compensation_repository.py -q`
acceptance_criteria:
  - `init_db` creates the new table idempotently.
  - Repository round-trips every estimate state.
  - Backfill does not mutate `jobs.salary` or `job_posted_compensation_facts`.
  - Repository rows never store raw benchmark pages, local paths, credentials, private account payloads, or user compensation preferences.
