# Phase 21 — UI Design Contract

> Visual and interaction contract for Jobs Triage UX & Warning-Only Floor. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | `b1VlJUeY` (`radix-luma`, neutral, Tailwind v4) |
| Component library | Radix/shadcn copied primitives under `apps/web/src/shared/ui` |
| Icon library | Tabler |
| Font | Geist sans for UI, JetBrains Mono for audit labels and compact metadata |

Source: `apps/web/components.json`, `corepack pnpm dlx shadcn@latest info -c apps/web`, `apps/web/src/styles/tokens.css`.

Implementation must use the existing app token layer and primitives. Do not introduce a new design system, third-party registry, charting package, table package, or icon library for this phase.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, compact dash/warning glyph spacing, `TitleStack` secondary gaps |
| sm | 8px | Tag gaps, table cell internal groups, disclosure summary gaps |
| md | 16px | Drawer mobile side padding, toolbar gaps, summary row spacing |
| lg | 24px | Desktop drawer section rhythm, major compensation summary grid gap |
| xl | 32px | Drawer viewport margin allowance and table minimum-width additions |
| 2xl | 48px | Reserved for major route-level separation only; avoid inside this dense phase |
| 3xl | 64px | Not used in Phase 21 Jobs table/drawer work |

Exceptions:
- None for new or touched Phase 21 spacing. If existing Jobs table or drawer styles are touched, migrate the affected padding to approved 4px-multiple values such as `8px 12px`, `16px 28px`, and `16px 16px`.
- Existing checkbox hitboxes keep `min-height: 36px`; new icon-only disclosure/filter controls must be at least `24px` visual size and reachable through the existing row/drawer focus order.
- Narrow Jobs table uses horizontal overflow and stable `min-width`, not column collapse.

## Typography

Use exactly these four sizes and two weights for new Phase 21 UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 400 | 1.5 |
| Label | 11px | 400 | 1.35 |
| Heading | 13px | 600 | 1.2 |
| Metric | 12px | 600 | 1.2 |

Rules:
- Do not scale font size with viewport width.
- Use `var(--font-mono)` only for compact labels, confidence bands, counts, source metadata, and policy/version stamps.
- Range and warning labels must wrap with `overflow-wrap: anywhere` in drawer evidence rows; table scan cells may ellipsize only when the full state is available via accessible label/title and drawer detail.
- Do not use hero/display typography in this operational surface.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `var(--card)` | App background, Jobs card, drawer surface, compensation audit section |
| Secondary (30%) | `var(--muted)` / `var(--border)` | Table header, inactive cells, evidence row backgrounds, separators |
| Accent (10%) | `var(--status-info)` / `var(--primary)` | Inspectable confidence/source metadata, active disclosure focus, official shadcn focus rings |
| Destructive | `var(--destructive)` | Destructive job actions only; not used for compensation floor warnings |

Accent reserved for:
- Table/drawer confidence state labels when confidence is informational.
- Source trail labels and progressive-disclosure affordances.
- Existing focus rings and active filter/disclosure states.

Warning color contract:
- Use `var(--warning)` and `var(--warning-muted)` for salary parse warnings, market-estimate warnings, source conflict, and profile-floor concerns.
- Warning states must include visible text and/or an icon with accessible text. Do not rely on yellow color alone.
- Muted unavailable or not-configured states use `var(--muted-foreground)` and `.tag.muted`, not warning color.
- Success/ok color is allowed only when a fact is confidently available or a floor comparison is clearly above the configured floor; it must not imply apply readiness.

| Element | Copy |
|---------|------|
| Primary CTA | No new primary CTA. Existing row activation remains "Open job"; existing Apply Review handoff remains "Open Apply Review". |
| Empty state heading | `No compensation facts recorded.` |

| Destructive confirmation | None added by this phase. Existing job delete/hide/permanent-delete confirmations remain unchanged. |

Required labels:
- Jobs table column headers: `Posted`, `Market`, `Warnings`.
- Table missing posted salary: visual `-`; accessible label `No posted salary recorded`.
- Table missing market estimate: visual `-`; accessible label must name the state, for example `Market estimate not requested`, `Market estimate unsupported`, `Insufficient market evidence`, or `Market source unavailable`.
- Drawer section title: `Compensation audit`.
- Drawer section eyebrow/kicker: `Warning-only salary evidence`.
- Floor not configured: `Floor not configured`.
- Floor basis labels: `Posted salary basis`, `Market estimate basis`, `Both posted and market`, `No comparable compensation basis`.
- Warning-only disclaimer: `Compensation warnings do not change ranking, filters, apply readiness, blockers, or dispatch in v1.3.`

## Surface Contract

### Jobs List

Primary visual anchor is the three-column compensation scan in the Jobs list. Drawer priority is top summary first, then evidence disclosures.

Add three separate display-only columns in `apps/web/src/views/jobs/columns.tsx`, after `Sources` and before `Location` unless implementation constraints require placing them after `Location` to preserve current scan order:

| Column | Width Contract | Content Contract | Interactions |
|--------|----------------|------------------|--------------|
| `Posted` | Stable compact scan cell, target 128-156px | Posted employer range from `row.compensationSummary.posted.displayRange`; visual `-` when absent/missing/unparseable/ambiguous without display range | Not sortable, not filterable, no row ranking effect |
| `Market` | Stable compact scan cell, target 144-176px | Market estimate state and range when `estimated_range`; otherwise compact state marker such as `unsupported`, `insufficient`, `unavailable`, or visual `-` with accessible label | Not sortable, not filterable, no row ranking effect |
| `Warnings` | Stable count cell, target 88-112px | Total compensation warning count from `row.compensationSummary.warningCount`, including floor warning only when a numeric profile floor exists and comparison produces a warning | Not sortable, not filterable, no apply readiness effect |

Table cell rules:
- Posted and market cells must use `row.compensationSummary`; do not parse `row.salary` in React.
- Keep posted and market visually separate even when both ranges exist.
- If `compensationSummary` is null, render compact muted `-` cells with accessible labels and do not derive compensation from legacy raw salary.
- `JobSummary.salary` may be shown only as legacy raw fallback context in drawer detail when no structured fact exists; it is not the normalized table source.
- Warnings cell must include text semantics such as `2 warnings`; icon-only warning counts are not allowed.
- Warning count must not include profile-floor comparison when no numeric profile compensation minimum exists.
- No salary sort, salary filter, salary rank, fit-score effect, apply-readiness state, hard blocker, Apply concern, or dispatch gate is introduced.

Responsive/table layout:
- Increase `.jobs-data-grid-table` minimum width enough to fit the three new columns without crowding; use intrinsic sizing, `minmax()`, `fit-content`, `min-inline-size: 0`, and horizontal `overflow: auto`.
- Preserve table row DOM and keyboard order. Do not collapse posted/market/warnings into a single mobile summary column.
- Prefer horizontal scroll over hiding compensation columns on narrow viewports.

### Job Drawer

Insert a dedicated `Compensation audit` section in `apps/web/src/views/jobs/JobDetailDrawer.tsx` immediately after `<JobAuditTriage detail={detail} />` and before the description section.

The section must use summary-plus-evidence:

| Region | Required Content | Layout |
|--------|------------------|--------|
| Top summary | Posted salary, market estimate, floor comparison | 3-column grid on wide drawers; single-column stacked rows below 1000px |
| Posted evidence | Parse state, display range, source field, allowed source excerpt/hash metadata, confidence, warnings, annualization assumption when present | Compact metric rows plus warning tags |
| Market evidence | Estimate state, range when available, match scope, confidence band/score, source/sample counts, company tier, source trail | Compact metric rows plus source rows |
| Floor comparison | Configured/not configured state, numeric floor when safely available, basis used: posted, market, both, or neither | Warning-only callout, never an Apply concern |
| Progressive disclosure | Source trail, confidence factors, assumptions, unavailable-source/insufficient/unsupported reasons | Native `details` or existing shared disclosure style; keyboard focusable summary |

Drawer state rules:
- Missing posted salary, unparseable posted salary, ambiguous posted salary, not-recorded facts, unsupported market estimate, insufficient evidence, source unavailable, and not-requested market estimate must render explicit text in the drawer.
- If no numeric profile compensation minimum exists, show muted `Floor not configured` and do not add a list warning count.
- If both posted and market values exist, display each basis separately and state whether the warning used posted salary, market estimate, both, or neither.
- The floor comparison may appear only in the compensation audit section and list warning count. It must not be added to `ApplyAudit`, Apply concerns, missing prerequisites, hard blockers, eligibility concerns, score factors, filters, ranking, or dispatch conditions.
- Compensation evidence must not expose raw benchmark pages, credentials, local paths, private profile data beyond safe comparison facts, or provider payloads.

Progressive disclosure:
- Use one closed disclosure for `Source trail` and one for `Confidence factors and assumptions` when details exceed the top summary.
- Each disclosure summary must include a count or state label, for example `3 sources`, `9 confidence factors`, `2 unavailable reasons`.
- Disclosure content must remain in DOM order after its summary and must not trap focus.
- `content-visibility`/containment is not required. Use it only if a self-contained heavy source/factor region becomes measurably expensive; the UI must remain correct without it.

## Interaction Contract

- Row click still opens the job drawer; compensation cells must not stop row activation unless a specific disclosure/button is added inside the drawer.
- Jobs table compensation columns are read-only. They do not open menus, sort, filter, rank, edit profile preferences, refresh compensation, import sources, or trigger apply/materials/pipeline actions.
- Drawer disclosure toggles are the only new interaction. They must be keyboard operable, visible in focus order, and have clear summary labels.
- Existing drawer close behavior, Escape key handling, Apply Review handoff, JobActions, StageTimeline, Apply history, and artifacts sections remain unchanged.
- Existing table sorting whitelist in `JobsView.tsx` must not add compensation sort fields in this phase.
- Existing filter UI must not add salary filters in this phase.

---

## Accessibility Contract

- Every visual dash in the Jobs table must have an accessible label explaining the missing/unsupported state.
- Warning/confidence states must include text; do not use color-only dots.
- Tags with `warn`, `info`, `ok`, or `muted` tone must preserve sufficient contrast in light and dark themes using existing tokens.
- Focus order must remain: row controls/table controls -> row activation -> drawer close -> overview -> audit triage -> compensation audit -> description -> actions -> diagnostics/history.
- Drawer disclosure summaries must be reachable by keyboard and readable by screen readers.
- Table horizontal scroll must be keyboard reachable through the existing grid scroll region and must not reorder DOM columns.
- Text must not overlap at desktop or mobile widths. Use `min-inline-size: 0`, wrapping in drawer evidence rows, and ellipsis only for compact table scan cells with accessible detail.

## Data And State Contract

Read sources:
- Jobs list uses `JobSummary.compensationSummary`.
- Job drawer uses `JobDetail.compensationAudit` and `JobSummary.compensationSummary`.
- Profile floor comparison uses only an existing numeric profile compensation minimum surfaced through the owning API/read-model path. Free-text salary expectations are out of scope.

Forbidden derived behavior:
- No React salary parsing.
- No API GET read-time salary parsing.
- No provider fetch/scrape/cache/import path.
- No source registry mutation.
- No profile preference edit flow.
- No compensation correction flow.
- No ranking/filtering/apply readiness/blocker/dispatch effect.

Fallback hierarchy:
1. Use structured posted summary/audit when present.
2. Show explicit missing/unavailable/unsupported state when structured data records that state.
3. Show legacy raw salary only as labeled fallback context in drawer detail, never as the normalized table range.
4. Show compact accessible `-` in list cells when no structured display value exists.

## QA Contract

Required automated coverage for Phase 21 implementation:
- `apps/web/src/views/jobs/JobsView.test.tsx` or focused colocated tests prove the three columns render posted, market, warnings, missing, unsupported, insufficient-evidence, source-unavailable, and null-summary states.
- `apps/web/src/views/jobs/JobDetailDrawer.test.tsx` proves the compensation audit section appears immediately after audit triage and before description.
- Drawer tests prove posted range, market estimate state, source trail, confidence factors, assumptions, warnings, unavailable-source reasons, and floor basis copy render from canonical fixtures.
- Tests prove no compensation column is sortable/filterable and `SORTABLE_JOB_FIELDS` does not include compensation fields.
- Tests prove floor warning count is omitted when no numeric floor exists and included only as warning-only compensation count when a numeric floor exists.
- A11y coverage or Storybook/RTL assertions prove dash cells and warning states have accessible labels/text.

Required manual/browser QA:
- Open `/jobs` with synthetic seeded compensation fixtures and verify horizontal table scroll on narrow width preserves separate `Posted`, `Market`, and `Warnings` columns.
- Open a Jobs drawer and verify the compensation audit section is directly below `Why this job is here`.
- Verify warning-only copy is visible and compensation does not appear in Apply concerns, missing prerequisites, hard blockers, fit score, ranking, filters, or apply dispatch controls.

Recommended commands:
- `corepack pnpm --filter @jobhunter/web test src/views/jobs/JobsView.test.tsx src/views/jobs/JobDetailDrawer.test.tsx`
- `corepack pnpm web:check`
- `corepack pnpm --filter @jobhunter/web e2e -- tests/jobs-drawer.spec.ts` when browser proof is added/updated
- `git diff --check`

QA data must be synthetic or seeded only. Do not run auto-apply, browser submission, mailbox scanning, real generated-material regeneration, destructive profile/database actions, real external scraping, or worker-backed jobs for this phase QA.
