# Complete product checklist

Use this checklist with the [risk selector](../../local-reliability-qa.md),
[regression catalog](regression-catalog.md) and [executed journey ledger](python-journeys.md).
The recurring suite is `corepack pnpm e2e`. Old unit/component/snapshot/RPC
recipes are retired. A checklist item requires observed product evidence; an
implemented route or an authored test is insufficient.

## High-risk regression areas

- Confirm the exact candidate, locked dependencies, actual Python API/worker,
  Temporal health and owned synthetic workspace. Record preparation and total
  time, failures and cleanup. Preserve unrelated state and processes.
- Read canonical source/receipt IDs for every visible evidence, requirement,
  person-fit, wording and document-coverage claim. Prove model authority and
  invalid/stale output refusal without a semantic fallback.
- Race saves/approvals, preserve local drafts and accepted newer versions, and
  require exact input hashes before external actions. Failed refreshes preserve
  accepted artifact bytes.
- Kill the actual worker mid-action, replace it with a new PID and inspect the
  original Temporal run and canonical state. Cancellation remains cancellation.
- Receive a synthetic application send without acknowledgement; restart and
  retry must retain Needs verification and make no second send.
- Exercise actual native/installed/cutover/provider proof separately where the
  change depends on it. Missing platform or provider access is a reported gap.

## Browser and accessible layout

Visit the changed screen at desktop and mobile width. Check page identity,
meaningful content, absence of framework overlays, relevant console errors,
keyboard focus, labels, dialog return focus, clipping/overflow, readable status
and a complete real interaction. Inspect fresh screenshots. Exercise navigation
and one live event connection; mutate through a second real client and require
query refresh. An event during a first in-flight read still requires a post-read
refresh. A stale background result cannot erase newer local edits or selection.

<a id="jobs-drawer-audit-smoke"></a>

## Jobs, requirements and person fit

Create a manual posting, race duplicates and inspect exact identity/provenance.
Extract a requirement through the real model gateway; reuse its canonical ID for
an explicit paraphrase verdict, preserve qualified distinctions and reject
unsupported/stale responses. Inspect person evidence and model receipt. A wording
gap cannot lower factual fit. Rejected/deferred wording proposals remain so.
Check optional Discovery/Companies omission leaves manual Jobs functional.

<a id="materials-generation--inspector-smoke"></a>

## Profile, wording and resume

Create an authored baseline with several roles and achievements, inspect source
references, propose exact alternative wording, approve it explicitly and compose
a deterministic full document. Retain every baseline role/achievement and exact
chosen IDs. Copying the baseline makes zero resume model calls. Edit through the
real editor, save as a draft, approve exact changes, review/render/accept and
export a real PDF. Inspect selectable text and rendered pages. Change a source
or race an editor save and refuse stale publication while retaining local work.
Fail the external model and Chromium process after acceptance; compare accepted
bytes. Explicit review override records its true status and keeps mechanical
source/approval checks.

<a id="apply-review-smoke"></a>

## Application review and outcomes

Prepare accepted resume bytes and screening answers, rehearse the exact payload,
approve that payload, then change an input and refuse the old permission.
Synthetic execution records intent before mail/ATS work and at most one attempt.
Lost/invalid acknowledgement and worker crash remain uncertain after restart.
Manual outcomes and email suggestions keep exact source/date/recipient linkage,
review/correction history and one request identity on retry. Unrelated mail must
not be fully fetched before a unique metadata link. Never submit a real
application or send a real message during QA.

<a id="outreach-planner-product-smoke"></a>

## Contacts and Outreach

Edit/import contacts and inspect provenance. Race contact fingerprints, research
through a real durable action and controlled external sources, then review exact
claims/drafts. Invalid model output preserves the approved draft. Revise from
the selected source draft, recheck stale copy/approval, set a date-only followup
and retry a user-attested send-log request after lost acknowledgement without
creating a second log. Clipboard/manual attestation is not automatic sending.

## Career, digest, compensation and offers

Create interview prep, sessions and notes and read them back after reload.
Choose/update a learning milestone and prove confirmed Profile evidence and Fit
are unchanged. Create/acknowledge a digest without changing sources. Inspect
compensation evidence, dates/currency/components and unknowns. Race policy/offer
versions, retain drafts on conflict, correct decisions and inspect history.
Optional owner omission must not break independent core capabilities.

<a id="browser-extension-qa"></a>

## Demo, extension and installed entrypoints

Demo uses owned browser storage, preserves approvals/accepted artifacts on
failure, and sends no production API requests. Test actual reload, cross-tab and
explicit reset behavior without using a real browser profile. Extension proof
loads the built extension in a real controlled Chromium profile and verifies
pairing/capability origin, capture and source limits; an early return because a
display is missing is nonpassing. Installed/source CLI and native launcher proof
uses real binaries, owned scopes and an unrelated control through stop/restart,
backup/rollback and explicit Profile-only transfer.

<a id="temporal-fault-injection-matrix"></a>

## Durable and operational matrix

Keep worker crash, cancellation, provider failure, ambiguous external effect,
process-inspection denial, controller interruption and Temporal-history loss as
distinct cases. Require original run/receipt identity, retained accepted state,
verified owned-process exit and a successful subsequent action where applicable.
Use the actual native platform for credentials, filesystem permissions, launchd
or Windows controls. Record each unexecuted case as a gap; do not infer it from
controlled HTTP or helper-process success.
