# Regression catalog

This catalog names the invariants that a real product or operational proof must
establish. The recurring executable owner is the [Python E2E journey suite](python-journeys.md).
The [QA selector](../../local-reliability-qa.md) chooses proof by risk. Historical
unit, component, snapshot, Fastify/RPC and isolated fixture commands are retired.

## Risk families

| Boundary | Required invariant |
| --- | --- |
| Sources and approvals | Exact canonical IDs, source revisions, text/payload hashes and explicit user authority survive round trips; a stale save or approval cannot replace newer accepted work |
| Meaning and fit | Only source-bound model decisions or explicit user corrections determine meaning/support; factual person fit never falls because wording is missing |
| Resume composition | Every baseline section, role and achievement is retained, including Language / Proficiency; exactly one current approved variant per achievement; one point per eligible canonical requirement then complementary depth and stable ties; no implicit brevity penalty |
| Accepted artifacts | Failed model/render/publication/refresh/cancellation preserves the accepted pointer and exact bytes; a failed candidate stays separate |
| Durable work | Actual Temporal acceptance, committed state/events, cancellation and real worker replacement keep one run identity and recover honestly |
| Submission | Exact reviewed payload, final revalidation, durable at-most-once intent, trusted receipt or explicit uncertainty; restart/reset cannot duplicate the send |
| Credentials and privacy | Native values never enter settings/events/logs; mutation rollback and process custody preserve peer writes; real OS behavior needs real platform proof |
| Frontend state | One SSE connection, post-read invalidation, version-fenced local edits, correct optimistic rollback and retained focus/selection; actual responsive/accessibility inspection |
| Optional features | Omitted registrations leave independent core features usable; public immutable snapshots replace sibling private-table reads |
| Runtime and cutover | One Python authority across HTTP/CLI/workers; legacy state is refused unchanged; explicit full-Profile transfer, paired backup/update/rollback and owned process controls |

## Auditability Checks

Before editing evidence, rationale, scoring, tailoring or approval behavior,
trace the reported UI claim through its recorded IDs to the canonical source.
Identify the owning feature and reproduce the failing invariant through the
actual public entrypoint. A renamed badge, hidden row or substituted rationale
does not prove a repair. Preserve the last accepted artifact on failed refresh.

For every semantic determination, inspect the actual prompt/source inventory,
provider/model/effort, lane/spend preflight and persisted receipt. Exercise
opposing valid choices for identical sources and failures for invalid schema,
unknown enums, forbidden fields, foreign IDs, non-verbatim quotes and stale
versions. An external test response is an explicit choice, never a lexical
matcher or a recorded replay corpus. Requirement matching must include the
complete incoming batch and canonical catalog in one determination, independent
of search-index freshness. Validate a complete decision partition and exact
catalog revisions before publication. Oversize, uncertainty and provider refusal
preserve accepted state without chunking or a separate novelty judge.

The `requirements-v2` language gate is a source-bound model decision before
extraction. Non-English postings skip extraction/Fit without translation or a
zero score. The reusable catalog holds Skills/Professional Experience only;
Education/Languages are direct job-local demands. Require one missing-set
qualification batch across all categories and permitted evidence per category.
Education may use professional experience only for the posting's explicit
alternative and must record the route without claiming a degree. Language
proficiency uses structured Language / Proficiency sources only. Reject
cross-section evidence. Inspect original occurrence meaning/evidence alongside
its canonical binding. Equal-item arithmetic uses distinct canonical meanings
and direct demands, with no source weights, must-have multiplier or blocker cap;
duplicates and alternatives cannot multiply points and an empty set has no score.

Profile owns facts, attachments, confirmations, authored baseline and wording
approval. Requirements owns qualified meanings and source occurrences. Fit
owns factual support and exact approved-wording coverage relations. Resumes
joins these recorded identities and owns document acceptance. A requirement
cannot prove a candidate fact; a wording proposal cannot approve itself; a
learning milestone cannot prove capability. Unknowns and correction history
remain visible. Rejected/deferred proposals are deduplicated rather than
regenerated for every posting.

Post-edit refresh of previously scored jobs requires explicit manual admission.
A job with no prior score may resolve only its fixed requirement set during
explicit first assessment even when older shared authority predates saved
changes. Require the no-prior-score fence, current-source and historical-head
comparisons, retained history and unchanged scores for every other job. Saves
and reads admit no work.
One source-bound impact selection sees the complete catalog and saved evidence
changes, including
previously missing/unlinked requirements. Only selected requirements require
new qualification; unaffected receipts retain their original semantic authority.
Exact current approved-wording bindings are direct reuse. Group actual wording
gaps by achievement and retain rejection/defer decisions across equivalent jobs.
Current section-backed matches are not achievement expression gaps. Require an
actual unsupported wording need and factual achievement support before a
proposal; existing approved expressions are reused without stylistic rewrites.
Saves, approval and the refresh's own writes never recursively admit work.
Race distinct action keys for the same profile, edits while queued/running,
catalog additions, cancellation and real worker replacement. Input snapshots,
scope and work counters survive retries; stale completion cannot silently widen
the task or consume a fresh allowance. Observe actual call counts and explicit
partial/refused results, not only the final score.

Race independent writers and mutate the posting/Profile during model inference.
A stale completion cannot publish over accepted current state. Retrying unchanged
inputs reuses current authority without another external model call. Committed
SSE must match canonical data and expose no private Profile/document/mail content.

A complete baseline composition retains all roles/achievements in authored order,
uses one exact approved wording per achievement and reports layout conflicts.
An unchanged input is deterministic. Baseline-copy and its review endpoint use
zero resume model calls. Advisory coherence is one review; explicit user override
records failed/findings/timeout honestly without bypassing mechanical approval,
source or PDF integrity. Inspect the exact selected variant IDs, requirement
coverage manifest, rendered text and accepted file digest together.
Exercise Language / Proficiency editing through Profile and Plate and inspect
text/PDF/DOCX/locale export retention with both current and older four-section
templates. An empty default creates no factual revision or content deletion.

For the generation boundary, use predecessor and candidate public application
entrypoints in owned synthetic state. Stop old writers and back up first. Keep
SQL schema strings byte-identical, legacy accepted rows and job ordering
unchanged, and accepted resume bytes intact. The active catalog starts empty;
old fields cannot promote meanings or establish current ranking/composition
readiness. Incompatible operation resumption/replay is refused. A failed
refresh keeps accepted pointers. After new writes, rollback restores the
pre-upgrade backup with compatible workflow state. This proof does not establish
a live rollout.

## Temporal fault injection

Start and inspect real workflows through Python HTTP/CLI. Hold only an external
provider/model boundary. Cancel through the real API, kill the actual worker,
start a distinct PID and verify the original run's durable result plus subsequent
successful work. Preserve accepted state and original external authorization.
No process pause, fabricated heartbeat, direct workflow-row seed or assertion
retry counts as recovery. Exercise worker loss after committed intent and before
acknowledgement; unknown submission stays uncertain with one external attempt.

## Rendered documents and evidence

Run the real renderer and export endpoint. Inspect the PDF signature, actual
selectable text, every retained role/achievement, page geometry and page images.
Ensure no clipped/overlapping/blank content, orphaned continuation, missing fonts
or hidden baseline sections. Editing requires exact approval before acceptance;
stale editor saves retain local work. Repeat a failed Chromium launch and an
invalid advisory response after acceptance and compare the prior accepted bytes.
HTML, PDF, DOCX and text export readers must use the same accepted revision.
Locale generation/review/acceptance keeps exact source revision and independent
review status; failed refreshes preserve the previous accepted locale.

Keep synthetic screenshots, PDFs, per-page images, command/tool/candidate
identities and setup/total timings outside the repository. A model choice proves
wiring and authority, not language accuracy. Report real-provider and installed
proof separately. The complete observed result belongs in the run evidence,
not in a historical assertion count.

## Acquisition, sources and retry

Manual capture and URL/source refresh preserve identity, source snapshots and
provenance. Race duplicate captures, source/checkpoint commits, catalog discovery
and cancellation. No rejected source or failed refresh may replace an accepted
posting or fabricate an observation. Optional automatic Discovery and Companies
must be removable while Jobs remains usable. Source policies and literal user
filters are respected; unsafe redirects and uncontrolled external URLs fail.
Company claims need explicit identity and exact selected public-source spans.

## Exact external effects

An application rehearsal previews the exact payload and accepted resume bytes.
Approval binds that payload and its sources. Changing inputs invalidates it before
intent or external work. An actual external receipt can confirm the recorded
intent; lost acknowledgement, malformed receipt or worker loss cannot. Refuse
reset/retry that could duplicate submission. A synthetic mail/ATS endpoint must
observe the actual request and exact attempt count. Manual outcome corrections
retain original evidence and idempotent request identity.

Outreach creates reviewed drafts and clipboard/manual-send records. It has no
automatic sender. Contact/source changes fence generation, approval and copy;
failed generation preserves the last approved draft. Retry a manual-send log
with the same request ID after a lost response and record it once.

## Native credential storage and migration

The ordinary suite replaces only the external OS command with an owned process;
actual HTTP, validation, user-scoped mutation lock, canonical settings and event
writers remain real. Exercise absent/configured/inspection-unknown status,
concurrent mutation, rollback preserving a peer write, invalid/oversized inputs,
interrupted native helper custody, malformed receipts and stale process identity.
Never log values or use a real contributor credential store.

Native macOS/Windows/Linux store behavior, private file permissions and access
control lists need actual fresh-platform namespace proofs. Installed lifecycle
needs the compiled launcher, real owned scopes, an unrelated control, process
birth/boot identity, descendant cleanup, bounded refusal, restart, paired backups
and update/rollback/retention. No mocked process census or fabricated ownership
flag establishes these outcomes. Keep unverified cases visible before release.

## Retained optional outcomes

Contact provenance/import/corrections and research claims stay source-bound.
Interview prep, notes and session history persist through the actual API and UI.
Learning plans/milestones never promote confirmed evidence or fit. Digest
creation/acknowledgement cannot mutate source records. Compensation preserves
sources, dates, currencies, units and components; unknown values remain unknown.
Offer decisions/corrections preserve full history and stale-version drafts.
Demo storage, extension transport and installed CLI are real separate entrypoints
and require their own product proof; normal application browser tests do not
establish them automatically.
