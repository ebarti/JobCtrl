# Backlog

[GitHub issues](https://github.com/ebarti/JobCtrl/issues) own new actionable work.
Each substantive maintainer request reuses or creates a short self-contained
issue with outcome, acceptance and context. Follow-ups retain that issue.
Issues are intake records; execution still needs an accepted scope and authority.

Current workflow adoption is [#879](https://github.com/ebarti/JobCtrl/issues/879);
issue-form triage is also tracked in [#798](https://github.com/ebarti/JobCtrl/issues/798).
The public direction remains [ROADMAP.md](../ROADMAP.md).

## Historical Notes

The former engineering backlog combined delivered work, old source observations,
conditional improvements and hosted-product plans. Its
[immutable source snapshot](https://github.com/ebarti/JobCtrl/blob/a1526649a395b9febb4c20ef30dd946945014a21/docs/backlog.md) remains available in Git.
Every source item has a [cutover disposition](developer/workflow-cutover.md#backlog-dispositions).
Unverified historical claims are explicitly deferred for code revalidation;
this cutover does not mark them fixed, Ready or authorized for execution.

Keep active accepted plans in `docs/plans/`; delivered plans belong in
`docs/plans/implemented/`. Record new accessibility and product regressions in
issues with the affected path, invariant, reproducer and acceptance criteria.
No known-failing web E2E spec is exempted from its applicable gate.
